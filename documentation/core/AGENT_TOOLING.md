# Agent tooling — `.claude/` and the instruction files

How AI coding agents are configured in this repository: which file each agent reads, what `.claude/`
contains, and how to add to it. The decision behind this layout is
[ADR-0007](../adr/0007-claude-code-harness.md). The rule it protects is
[ADR-0006](../adr/0006-one-agent-contract.md): **every rule lives in [`AGENTS.md`](../../AGENTS.md)**.

## The layout

```text
AGENTS.md                 the contract: every rule, read by every agent (< 200 lines)
CLAUDE.md                 Claude Code entry point: imports AGENTS.md, nothing else
GEMINI.md                 Gemini CLI entry point: imports AGENTS.md, nothing else
.worktreeinclude          gitignored files copied into new worktrees (backend/.env, frontend/.env.local)
.claude/
├── settings.json         committed: attribution off, permissions, hook wiring (protected file)
├── settings.local.json   gitignored: your personal overrides
├── hooks/
│   ├── agent_guard.py         PreToolUse: asks on protected files, refuses bad commits, history rewrites, .env prints
│   ├── session_context.py     SessionStart: branch, dirty files, locked versions, next BUILD_ORDER task
│   └── test_agent_guard.py    self-test; run it whenever hooks/ or AGENTS.md § 1/§ 4 formatting changes
├── rules/                pointer-only, path-scoped: load when matching files are opened
│   ├── backend.md            backend/**/*.py
│   ├── migrations.md         models and migrations
│   ├── frontend.md           frontend/src/**, frontend config
│   ├── documentation.md      documentation/**, README.md
│   └── agent-config.md       .claude/**, AGENTS.md, CLAUDE.md, GEMINI.md
├── skills/               procedures, loaded on demand; each cites where its rule lives
│   ├── verify/               /verify — the AGENTS.md § 2 gate, reported honestly
│   ├── changelog/            /changelog — the DAILY_CHANGES entry + every other register
│   ├── commit/               /commit — user-invoked only; pre-push scans, § 4 message
│   ├── next-task/            /next-task — next BUILD_ORDER item; stops at 🚧 DECISION
│   ├── adr/                  /adr — record or supersede a decision
│   ├── bug-class-check/      /bug-class-check — BUG_CLASSES.md sections by area
│   └── new-django-app/       /new-django-app — DJANGO_STANDARDS § 2, done in full
├── agents/               subagents, each in its own context window
│   ├── code-reviewer.md      read-only review against the contract; memory: project
│   ├── doc-auditor.md        read-only doc-vs-code drift audit; memory: project
│   └── implementer.md        one spec, listed files only, no git writes
└── agent-memory/         committed, public: what the memory-enabled subagents learn
```

## Which file each agent reads

| Agent | Reads | Enforcement |
|-------|-------|-------------|
| Claude Code | `CLAUDE.md` → `@AGENTS.md`, plus `.claude/` | hooks + permissions |
| Codex, Cursor, GitHub Copilot, OpenCode | `AGENTS.md` natively | none, so the written rules apply |
| Gemini CLI | `GEMINI.md` → `@AGENTS.md` | none |

With a root `CLAUDE.md` present, Claude Code reads `CLAUDE.md` files rather than `AGENTS.md` files, so the
import is what loads the contract. `frontend/AGENTS.md` is generated by `next dev` and is loaded by Claude Code
through `frontend/CLAUDE.md`.

## What the guard does

| Situation | Decision | Rule |
|-----------|----------|------|
| `Edit`/`Write` to a file in `AGENTS.md`'s protected list, or a Bash command that writes one | **ask**: you get a prompt, even in auto mode | § 1 protected files |
| `Edit`/`Write` to `frontend/AGENTS.md` | **deny**: it is regenerated by `next dev` | § 1 |
| `git commit` whose subject is not `<type>(<scope>): <description>`, is over 72 characters, ends in a period, or has no blank line before the body | **deny** | § 4 |
| a commit message with a `Co-Authored-By` naming an AI tool, a "Generated with" line, 🤖, or a tool link | **deny** | § 4 |
| `push --force`/`-f`/`--force-with-lease`/`+ref`, `push --delete`/`:ref`, `reset --hard`, `branch -d/-D`, `--no-verify`, `filter-branch`/`filter-repo` | **deny** | § 1 rules 2, 4 |
| `cat`/`head`/`tail`/… of a real `.env` file (`.env.example` is fine) | **deny**, with a key-names-only alternative | § 1 rule 6 |
| a git command the guard cannot parse | **ask** | — |

The protected list and the commit types are parsed from `AGENTS.md`, so editing that file is the only way to
change them. Bash parsing is best-effort: it is a guard rail, not a security boundary (ADR-0007).

## Adding to it

- **A new rule** goes in `AGENTS.md` (a protected file, so ask), or in the `system-design/` doc that owns
  it. Never in `.claude/`.
- **A new procedure** becomes a skill: `.claude/skills/<name>/SKILL.md`. Its `description` says when to use it.
  It cites the rule's home rather than restating it, and stays under 500 lines. Use
  `disable-model-invocation: true` for anything with side effects.
- **A new path-scoped pointer** goes in `.claude/rules/<topic>.md`, with `paths:` frontmatter and a list of
  docs to read. No rule text.
- **A new subagent** is `.claude/agents/<name>.md`. Give it least-privilege `tools` and `disallowedTools: Agent`.
  If it has `memory: project`, tell it that its memory is public.
- **A hook change** needs a matching case in `test_agent_guard.py`, then a run of it.
- **Personal preferences** go in `.claude/settings.local.json` or `CLAUDE.local.md`. Both are gitignored.
