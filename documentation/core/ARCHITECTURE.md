# Architecture

**How the two halves fit together, as of 2026-09-15.** This file describes what **exists**. Anything
planned is marked 🔜 and lives properly in [`../planning/ROADMAP.md`](../planning/ROADMAP.md).

---

## The shape

```
Browser
   │
   │  http://localhost:3000
   ▼
┌──────────────────────────────┐
│  Next.js 16 (App Router)     │   frontend/
│  React 19 · Tailwind 4 · TS  │
│                              │
│  src/app/      routes        │
│  src/lib/api.ts  ← the ONLY  │
│                  place that  │
│                  talks HTTP  │
└──────────────┬───────────────┘
               │  NEXT_PUBLIC_API_URL
               │  http://localhost:8000
               ▼
┌──────────────────────────────┐
│  Django 5.2 + DRF            │   backend/
│                              │
│  config/    settings · urls  │
│  core/      health · shared  │
└──────────────┬───────────────┘
               ▼
        SQLite (dev) / PostgreSQL (DATABASE_URL)
```

Two processes, two toolchains, one HTTP boundary. They are deployable independently, and that is the
point of [ADR-0002](../adr/0002-api-first-drf-not-django-templates.md).

## Backend

### Layout

| Path | Holds |
|------|-------|
| `backend/config/` | The Django project package — `settings.py`, `urls.py`, `asgi.py`, `wsgi.py` |
| `backend/core/` | The base app: the health probe and anything genuinely shared |
| `backend/manage.py` | Entry point. Always run it as `uv run python manage.py ...` |

**A new domain is a new Django app**, registered in `INSTALLED_APPS` and included from
`config/urls.py`. `core/` is not a dumping ground — it is for what more than one app needs.

### Routes that exist today

| Route | What |
|-------|------|
| `/admin/` | Django admin — a staff tool, not a product surface |
| `/api/health/` | Public liveness probe (`core.views.HealthView`) |
| `/api/schema/` | OpenAPI 3 document, generated by drf-spectacular |
| `/api/docs/` | Swagger UI |

That is the whole API surface. There is no auth endpoint, no user endpoint, no CRUD.

### Settings

Everything environment-dependent comes from `.env` through `django-environ`, read in
`config/settings.py`. Nothing is hard-coded. The keys are listed in `backend/.env.example` —
**values never appear in docs, output or commits.**

### DRF defaults — and the one open tension

`REST_FRAMEWORK` in `config/settings.py` sets:

| Setting | Value | Why it matters |
|---------|-------|----------------|
| `DEFAULT_PERMISSION_CLASSES` | `IsAuthenticated` | **Fails closed.** A new view is private unless it opts out. Opting out is explicit, per-view, and should be rare |
| `DEFAULT_AUTHENTICATION_CLASSES` | `SessionAuthentication` | Django's session cookie |
| `DEFAULT_PAGINATION_CLASS` | `PageNumberPagination`, `PAGE_SIZE: 20` | Every list is paginated by default |
| `DEFAULT_THROTTLE_CLASSES` | `AnonRateThrottle`, `UserRateThrottle` | Basic rate limiting is on |
| `DEFAULT_SCHEMA_CLASS` | drf-spectacular `AutoSchema` | Every view appears in the OpenAPI doc |

> ⚠️ **`SessionAuthentication` above is a placeholder.** The auth model is decided
> ([ADR-0009](../adr/0009-jwt-in-httponly-cookies.md)): JWT in `httpOnly` cookies backed by DB session
> rows. `CookieJWTAuthentication` replaces it in `BUILD_ORDER` 1.1b. No endpoint authenticates yet.

## Frontend

### Layout

| Path | Holds |
|------|-------|
| `frontend/src/app/` | Routes. App Router — a folder with `page.tsx` is a route |
| `frontend/src/lib/api.ts` | The typed fetch wrapper. **The only module that makes HTTP calls** |
| `frontend/public/` | Static assets served from `/` |

### The API boundary

`src/lib/api.ts` exists so that the base URL, error handling, headers and (🔜) auth token refresh are
written once. A component that calls `fetch()` directly bypasses all of it and will be wrong in a way
that only shows up in production. `AGENTS.md` § 3 makes this a hard rule.

`NEXT_PUBLIC_API_URL` is the base, defaulting to `http://localhost:8000`.

> ⚠️ `NEXT_PUBLIC_*` variables are **inlined into the client bundle** and are public. A secret must
> never take that prefix.

### Next 16 specifics

React 19 and Next 16.3.4. `params` and `searchParams` are **async** — advice written for Next 13/14
will not compile. The bundled agent docs at `frontend/node_modules/next/dist/docs/` are the source of
truth; read them rather than recalling.

## What does not exist yet

Stated plainly, because assuming otherwise wastes time:

- **No authentication.** No login, no tokens, no `/me`.
- **No authorization beyond DRF's `IsAuthenticated`.** No roles, no groups wired up, no object-level
  permissions.
- **One model.** `users.User` ([ADR-0008](../adr/0008-custom-user-model-email-identity.md)); no domain models yet.
- **A young backend test suite.** `uv run pytest` with `config.settings_test`, a root `conftest.py` (test-database guard, cache isolation) and factories in `backend/tests/`. No frontend runner, no CI.
- **No CI.** Nothing runs the verification gate except a person.
- **Docker for development only, no deployment.** `docker-compose.yml` runs both apps with live reload ([`README.md`](../../README.md) § Getting Started). See [`../system-design/DEPLOYMENT.md`](../system-design/DEPLOYMENT.md) § 0.
