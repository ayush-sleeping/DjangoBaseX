# Tech Debt

**Every known defect, gap and deferred decision — ranked.** Check here before reporting something as
a new discovery; if it is listed, it is known.

Adding a row is part of the same change that creates the debt (`AGENTS.md` § 4). A row is closed by
striking it through with the date, not by deleting it — a deleted row loses the evidence that the
problem was real.

**Ranking:** 🔴 blocks a deploy · 🟠 will cause a real bug · 🟡 costs time repeatedly · 🟢 tidiness

| **DB-11** | 🟡 | **No readiness probe** | `/api/health/` answers without checking the database. A liveness probe that stays green while the DB is down keeps a broken instance in the load balancer |
| **DB-12** | 🟡 | **Postgres-only features pass locally on SQLite** | [ADR-0005](../adr/0005-sqlite-for-dev-postgres-by-url.md) accepts this. Nothing catches it — no tests, no CI. Mitigated once CI runs against PostgreSQL 16 |
| **DB-13** | 🟢 | **No seeders or fixtures** | Resetting local data means `createsuperuser` by hand. A `seed` management command would make it one repeatable step |
| **DB-14** | 🟢 | **`known-first-party` is a manual step** | Each new Django app must be added to `backend/pyproject.toml`. Forgetting it makes Ruff fail on files nobody touched — a misleading symptom for a trivial cause |
| **DB-15** | 🟠 | **`/admin/` is an unguarded second auth system** | `config/urls.py` mounts it unconditionally. It authenticates by session (not `CookieJWTAuthentication`), authorizes on `auth_permission` (not the RBAC catalog), sits outside `/api/` so `dbx.E001` and the route test never see it, and writing `rbac_*` rows through it bypasses the elevated-role and last-superuser guards **and writes no `ActivityLog`**. Fixed by `BUILD_ORDER` **1.7** — `ADMIN_ENABLED`, and the `rbac` models not registered. See `AUTH_BLUEPRINT.md` Ch. 20 |
| **DB-16** | 🟡 | **No scheduler, so retention runs by cron** | `AUTH_BLUEPRINT.md` § 19.2 needs `auth_cleanup` run daily; `users_login_attempt` grows with attack traffic rather than user count. Celery is Phase 2, so until then this is a crontab entry the deployer has to remember — which is to say, an unenforced requirement |
| **DB-17** | 🟡 | **A shared cache is a correctness requirement, not a performance one** | The permission-version counter, session liveness and every throttle live in `django.core.cache`, which defaults to per-process `LocMemCache`. `dbx.E005` (`BUILD_ORDER` **1.0**) refuses to boot that way with `DEBUG=False`, but until 1.0 lands nothing says so. `AUTH_BLUEPRINT.md` § 17.4 |
| **DB-18** | 🟠 | **Plugin import would swallow a broken plugin as "absent"** | `AUTH_BLUEPRINT.md` § 7.2 says only `ImportError` is swallowed when a plugin fails to import. A typo *inside* a present plugin raises `ModuleNotFoundError` too, so the plugin silently disappears — missing permissions and 404s are the only symptoms. Fix in the spec before 3.1 is built: catch only when `exc.name` is the plugin's own package, re-raise otherwise, and test both cases. `PLATFORM_BLUEPRINT.md` § 5 row 1, `EXTENSIBILITY.md` |
| **DB-19** | 🟠 | **Production-safety rules exist only as system checks** | `dbx.E005`–`E008` are Django system checks, which run on `manage.py` commands but **not** when gunicorn/uvicorn serves the app. The same audit must also run at settings import and raise `ImproperlyConfigured`, reporting every problem at once, with a CI step proving a dev config refuses to import under `APP_ENV=production`. `CONFIGURATION.md` |
| **DB-20** | 🟠 | **Planned cookie paths are invisible to page navigations** | `AUTH_BLUEPRINT.md` § 6.1 scopes the access cookie to `/api/` and the refresh cookie to `/api/auth/refresh/`. Any Next.js edge route guard then sees no cookie on a page request and bounces signed-in users once the access token expires. Add a `Path=/` httpOnly session **marker** cookie (no credential in it) before building any route guard. `FRONTEND_PLATFORM.md` |
| **DB-21** | 🟡 | **Machine-caller authorization model undecided** | `API_DESIGN.md` says machine callers are principals with permissions. The alternatives — abilities that never satisfy a permission check, or scopes equal to permission strings with two gates (credential scope **and** owner's live permission) — are compared in `API_PLATFORM.md`. Decide and write the ADR before the first token endpoint |
| **DB-22** | 🟡 | **`PUBLIC_ROUTES` has no plugin seam** | `AUTH_BLUEPRINT.md` § 9.2 keeps the public-route ledger as a core-only dict, so a plugin must edit core to add an anonymous endpoint. Make it `registry.public_routes`; the route test and `dbx.E007` read the union. `EXTENSIBILITY.md` |
| **DB-23** | 🟡 | **Tenancy decision (`DATA_MODEL.md` D3) lacks the cost evidence** | D3 recommends no organisation model in core. A studied core concluded the opposite and measured the retrofit at 258 function signatures. Whichever way D3 is decided, record that cost in its ADR. `REUSABLE_MODULES.md` § tenancy, `DATA_LIFECYCLE.md` |
| **DB-24** | 🟢 | **The API prefix is not a single constant yet** | `API_DESIGN.md` defers `/v1/`. Moving a prefix later silently breaks cookie paths, throttle tables and client interceptors keyed on literal paths. Centralise `API_PREFIX` in settings now and derive every path from it. `API_PLATFORM.md` |
| **DB-25** | 🟠 | **The documented `SECRET_KEY` recipe can produce a key django-environ misreads** | `README.md`, `NEW_PROJECT.md` and `ONBOARDING.md` generate the key with `get_random_secret_key()`, whose alphabet includes `$`. django-environ treats a value that **starts** with `$` as a reference to another variable (verified in the installed `environ/environ.py`: the `$` is stripped and the rest looked up), so roughly one generated key in fifty resolves to something else or fails to boot. Use `secrets.token_urlsafe(50)`. `OPERATIONS.md` § 21 |
| **DB-26** | 🟠 | **`__Host-` on the access cookie contradicts its `Path=/api/`** | `AUTH_BLUEPRINT.md` § 17.5 applies `__Host-` to the access and CSRF cookies; § 6.1 scopes the access cookie to `Path=/api/`. `__Host-` requires `Path=/`, so the browser would reject the cookie. Resolve together with **DB-20**: `__Secure-` for path-scoped cookies, `__Host-` only for `Path=/` ones. `FRONTEND_PLATFORM.md` conflicts table |
| **DB-27** | 🟡 | **DB-11 describes the health view inaccurately** | `backend/core/views.py::HealthView` *does* run `SELECT 1` and answers 503 on failure — so `/api/health/` is an unbounded readiness probe (no timeout) documented as liveness, and it returns a hard-coded product name on an unauthenticated endpoint. DB-11 is left as written for the record; the fix is the three-rung design in `OBSERVABILITY.md` (`BUILD_ORDER` **6.2**) |
| **DB-28** | 🟡 | **The planned frontend plugin symlink needs a Turbopack root** | `CORE_ARCHITECTURE_PLAN.md` § 5 symlinks `plugins/<name>/frontend` into `frontend/src/plugins/`. The bundled Next.js docs say Turbopack does not resolve files outside the project root, so `turbopack.root` must be set in the **protected** `frontend/next.config.ts` before Phase 3.5. `EXTENSIBILITY.md` conflicts table |
| **DB-29** | 🟡 | **Concurrency guarantees are Postgres-only; SQLite dev silently ignores them** | `select_for_update()` is a no-op on SQLite, and the planned audit-log triggers, exclusion constraints and independent audit connection only exist on Postgres. Numbering, ledger and audit tests must run in the Postgres CI job, never only locally. Extends **DB-12**. `DOMAIN_PRIMITIVES.md`, `DATA_LIFECYCLE.md` |
| **DB-30** | 🟠 | **Today's anonymous throttle is bypassable by rotating `X-Forwarded-For`** | `config/settings.py` enables `AnonRateThrottle` with DRF's `NUM_PROXIES` unset. In that case DRF's `get_ident()` keys the bucket on the **entire client-supplied `X-Forwarded-For` header** (verified in the installed `rest_framework/throttling.py`), so any client gets a fresh bucket per request by changing the header. Set `NUM_PROXIES` from `TRUSTED_PROXY_COUNT`, or route throttle identity through `client_ip()` (`BUILD_ORDER` **1.0**). The same settings block pins no renderer or parser classes, so the browsable HTML API and form-encoded bodies are live. `API_PLATFORM.md`, `BUG_CLASSES.md` |
| **DB-31** | 🟠 | **The planned "401 → refresh once" contract will receive 403** | DRF downgrades `NotAuthenticated` to **403** when the first authenticator has no `authenticate_header()` (verified in the installed `rest_framework/views.py`). `AUTH_BLUEPRINT.md` § 11's client refreshes on 401 only, so without a `WWW-Authenticate` value on the cookie authenticator an expired session is never refreshed. Specify `authenticate_header()` in § 6.4, and test that an anonymous request gets 401. `API_PLATFORM.md` conflicts table |
